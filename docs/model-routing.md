# 手工统一模型路由

管理员在「模型 → 统一模型路由」创建调用名称，选择实际渠道模型并调整优先顺序。例如将 `deepseek-flash-pool` 关联至 `workbuddy/deepseek-v4.1-flash` 和目录中确实可用的 Trae 模型；模型是否等价由管理员确认，不根据名字自动合并。

调用名称允许没有前缀，不能覆盖已有模型、别名、`auto` 或渠道命名空间，保存后不能改名。WorkBuddy公开目录显示 `workbuddy/` 前缀，旧裸模型名称依旧直连WorkBuddy。

每次请求按当前Key、用户账号归属与共享组权限筛选成员；有图片的请求只使用目录明确支持图片的成员，显式输出上限超过成员能力时跳过。公开统一模型能力显示成员共同支持的保守值；不同渠道的价格/倍率单位不直接比较或合并。

成员顺序决定初次渠道选择，成功调用会绑定逻辑会话渠道（30分钟闲置有效期，内存保存，重启清空）。进入渠道后继续沿用该渠道原有账号策略。响应尚未开始时，429或5xx最多尝试两个成员；各渠道内部已有的有限重试保留。400/403、普通审核拒绝和已经开始输出的响应不会跨渠道重放。

带服务端response续接ID、加密推理内容或签名思考内容的请求需要已有原渠道粘性；原渠道不可用时明确拒绝，请改用物理渠道模型或客户端支持的完整历史，不会删除不透明状态来强行切换。

客户端收到的响应模型名保持统一调用名称，计费、用量和预计续航仍按真实物理渠道归集。调用诊断保留逻辑与物理模型名称。

受限Key保存模型白名单时冻结当前统一模型成员。之后增加成员不会自动授予该Key新渠道权限；重新保存Key模型权限才授权当前成员。删除再同名重建不会恢复旧授权。门户还必须满足实际成员的用户权限与全局禁用规则，统一模型不会开放尚未启用的渠道共享池。

此功能升级数据库至schema20。代码回退到旧版本时，应使用升级前数据库快照配套回退；只切换二进制不等于完整数据库回退。
